# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Start Vite dev server with HMR
- `npm run build` — Type-check with `tsc -b` then build with Vite
- `npm run lint` — ESLint across all TS/TSX files
- `npm run preview` — Preview production build locally
- `npm run gen:api` — Regenerate `src/types/api-schema.ts` from `openapi/documentation.yaml`
- `npm run sync:spec` — Copy the latest spec from the sibling `../MysteryBox-ktor` checkout, then run `gen:api`

To verify a change: `npm run lint && npm run build`. If `openapi/documentation.yaml` changed, also run `npm run gen:api` and commit the result (CI fails when the generated types are out of sync).

## Tech Stack

- **React 19** with TypeScript (~5.9), bundled by **Vite 7**
- **React Router 7** (`react-router-dom`) for client-side routing
- `openapi-typescript` generates API types from the backend's OpenAPI spec
- ESLint 9 flat config with `typescript-eslint`, `react-hooks`, and `react-refresh` plugins
- No test framework configured yet
- No CSS framework — plain CSS (`App.css`, `index.css`)

## Project Structure

- `src/main.tsx` — Entry point, renders `<App />` inside `<StrictMode>`
- `src/App.tsx` — Root component; defines routes (`/`, `/download`, `/privacy`, `/account-deletion`)
- `src/pages/` — One component per route, plus legal page content (`legalContent.ts`)
- `src/api/` — Fetch-based API client (`client.ts`), base URL config, and per-resource modules
- `src/types/api-schema.ts` — Generated by `npm run gen:api`; never edit by hand
- `src/i18n.ts` — `zh`/`en` translation strings; `src/constants.ts` — store URLs and shared constants
- `openapi/documentation.yaml` — Vendored copy of the backend spec
- `vite.config.ts` — Vite config with `@vitejs/plugin-react` (Babel-based)
- `tsconfig.json` — References `tsconfig.app.json` (app code) and `tsconfig.node.json` (tooling)

## Branching & PR Strategy

- Feature and fix branches target **`develop`** (not `main`)
- `develop` → `main` PRs are **release PRs** — they trigger CD for production deployment
  - Title format: `Release: <short summary>`
  - The PR body must include a summary of all changes since the last release (list merged feature/fix PRs)
  - Do not squash-merge release PRs; use a merge commit to preserve history

## CI/CD

- **CI** (`.github/workflows/ci.yml`) — Runs lint & build on PRs to `main` (opened/synchronize/reopened)
- **CD** (`.github/workflows/cd.yml`) — Deploys to Firebase Hosting when a PR to `main` is merged
- **API Types** (`.github/workflows/api-types.yml`) — Fails PRs to `main`/`develop` when `src/types/api-schema.ts` is out of sync with the spec
- **Claude Auto Review** (`.github/workflows/claude-auto-review.yml`) — Reviews PRs to `develop`/`main`, pushes material fixes, and posts one review comment
